# 开发流程

依据：DEV_PLAN.md v1.0（2026-10-16）。本文只细化实施流程，不替代原规范。

## 规范与范围

1. 第 6 节的数据契约、第 7 节参数与默认值为唯一事实来源。
2. 第 15 节规定 M0–M9 顺序；第 14、16 节规定测试、验收和 ES3 约束。
3. 碰到冲突或缺失行为时，采用最简单、可预测的方案并记入 DECISIONS.md；不自行扩展功能。
4. P0 必须、P1 应完成、P2 可选。每个里程碑通过验收后才能进入下一个；Illustrator 实测缺失时记录待验证。
5. 首次交付 M0 已完成；用户现已授权继续按里程碑开发，直到必须由用户验收的节点停下。当前远程为私有 GitHub 仓库 `diseno1210/logo-guides-illustrator`，每个里程碑提交后推送 `main`。M1 真实 DumpGeometry、M2 实际绘制已验收；后续强制用户门槛为 M6 第14.5节。
6. 用户已委托代理继续验收与开发。可使用真实Illustrator脚本接口与桌面控件操作收集证据；原生DOM不等于Node替身，但DOM修改/duplicate也不等于清单指定的直接选择/Alt拖动。仅在工具无法可靠完成的实际操作上交接用户，不以工具限制省略验收项。

## 每个里程碑的操作顺序

1. 阅读相关章节与前一里程碑证据，列出对应模块和验收夹具。
2. 实现该里程碑能力；core 保持纯函数、ES3、无宿主依赖，host 保持薄层。
3. 执行自动测试、构建、ES3 检查及 SVG 预览；修复后重跑相关验证。
4. 原文要求 Illustrator 验收时，提供可运行产物和手动步骤，将实测记录独立保存；不以 Node 测试替代。
5. 更新 STATUS、DECISIONS、CHANGELOG、USER_GUIDE，记录命令、证据和限制。
6. 检查暂存内容，无密钥和生成文件；以一次有意义的提交保存可复核结果。
7. 满足全部验收条件后标为已验收；尚缺外部实测时不进入下一里程碑。

## M0 实施清单

- 工作区直接作为根目录；主文档迁入 docs，原始导出版归档，正文不改。
- 初始化本地 main，沿用现有 Git 作者，先提交文档和仓库基础。
- 建立原文第 5 节模块目录，未来模块不伪装成已经实现的接口。
- package 仅使用 acorn、svgpath、@xmldom/xmldom 三个固定版本开发依赖，以 package-lock.json 锁定；Node 20+。
- build 按编号顺序拼接 core → host → 入口，包 IIFE，加 #target illustrator，转义非 ASCII 后检查 ES3。
- 检查器用 acorn AST 验证语法与禁用 API；保留 indexOf/lastIndexOf 与行末 es3-ok 例外。
- vm 加载同一份 core，先删除禁用 API；禁止伪造 analyze 分析结果。
- F1 采用四段贝塞尔圆；预览支持 Geometry JSON / SVG；两组 id 固定为 lg-geometry / lg-guides。
- Chrome 无头截图核对 F1；全新 npm ci 后执行全部验收，记录证据并提交。

## Git 与发布

- 初始分支 main。文档/仓库基础提交后，M0 验收通过再提交工具链。
- 原文规定的版本节点为 M6 v0.1、M7 v0.2、M8 v0.3、M9 v1.0；M0 使用开发版本，不提前打发布 tag。
- 只提交明确列出的项目文件；生成产物和机器路径不写入源码。仓库文本 LF；生成 JSX 全 ASCII。
- 远程仓库：`https://github.com/diseno1210/logo-guides-illustrator`，当前为 private，默认分支 `main`。
- 每个里程碑完成自动验证、文档和必要宿主证据后，执行一次有意义的提交并 `git push origin main`；推送前检查工作区、敏感文件和构建产物均未入库。
- 其他 agent 审查时以 GitHub `main` 最新提交和对应里程碑文档为准；审查意见应关联提交、文件和验证证据。
