# M9 签名与安装实施计划

前置：M8已验收，v0.3.0，提交5648724。依据DEV_PLAN第11.5、15、16节；主规范正文不改。

1. 使用Adobe官方ZXPSignCmd、自签名证书打包ZXP；记录工具来源、固定提交、SHA256及实际签名验证结果。签名工具和证书留在被忽略的本机目录，密码不写源码、日志或提交。
2. 发布工具使用Node内置模块，重新构建并校验版本、ES3和明确的文件清单；从干净暂存目录签名，拒绝符号链接、调试文件、用户配置及意外文件。产物位于dist/releases，不入Git。
3. 提供证书创建、打包和独立验证入口；打包后校验签名并核对归档内容与构建内容，输出文件清单与SHA256证据。证书创建失败、签名失败或验证失败不得留下可误用的成品。
4. 更新安装、升级、卸载、回退与故障说明，区分脚本和CEP，保留原脚本目录/快捷键/settings说明。提供干净机器验收表及具体待验包，不要求终端用户开启PlayerDebugMode。
5. 自动测试覆盖清单、版本冲突、意外文件、符号链接、敏感文件、签名失败及校验失败；执行全部回归、构建/ES3和一次真实签名校验。本机已有开发扩展不能替代干净机器安装。
6. 记录本机证据并提交推送GitHub，同步既有Notion日志。干净机器安装未通过时M9保持待验收、版本仍为0.3.0；通过后统一更新版本、重新打包并验证最终v1.0制品。不得把预验包称为v1.0正式版。

本轮只完成M9范围，不新增算法、面板功能、依赖或自动发布GitHub Release/tag。README保留远端fe65875的清空变更。
